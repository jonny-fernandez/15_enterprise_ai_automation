# Project Rules — Enterprise AI Automation & Distributed Data Integration Platform

1. Build checkpoint-by-checkpoint. Do not skip prerequisite validation.
2. Deterministic calculations, validation, and business rules are authoritative.
3. AI may interpret verified outputs, but must not invent metrics, model results, evidence, or system state.
4. Prefer reproducible configs, explicit seeds, versioned artifacts, and documented environment assumptions.
5. Add automated tests as capabilities are introduced; discovered failures should become regression tests where practical.
6. Preserve negative results. Do not force advanced methods to appear superior to simpler baselines.
7. Use synthetic or portfolio-safe data only. Never include employer-confidential data or PII.
8. Do not add a technology solely for a résumé keyword; it must solve a real project requirement.
9. Before GitHub publication, complete a technical/security audit and secret scan.
10. After technical completion, but before final README/GitHub publication, provide a Word screenshot handoff containing:
    - every final screenshot,
    - the exact PNG filename,
    - a short description of what the screenshot proves.
11. Wait for screenshot confirmation before finalizing/publishing the GitHub repository.
